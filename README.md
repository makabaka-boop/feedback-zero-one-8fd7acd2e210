# sparse_rows — MySQL 8.4.11 稀疏行镜像采集

从零实现的 Python 程序：读取 `TABLE_MAP_EVENT` 与三种 V2 行事件
（`WRITE_ROWS_EVENT_V2` / `UPDATE_ROWS_EVENT_V2` / `DELETE_ROWS_EVENT_V2`）
拼接而成的字节流，输出 JSON 变更数组。解析完全自写，仅用标准库
（`zlib` 提供 CRC32，`json` 仅用于输出序列化）。

格式依据：MySQL 8.4.11 `rows_event.h`（事件布局）及同版 `json_binary`
二进制 JSON 格式。

## 用法

```
python3 sparse_rows.py [--trace] INPUT [OUTPUT]
```

- `INPUT`：事件字节流文件，`-` 表示标准输入。
- `OUTPUT`：JSON 输出文件；省略或 `-` 表示标准输出。给定真实路径时，
  先写同目录临时文件再原子 rename —— **只有整次解析成功才替换输出**，
  失败时既有输出文件原样保留。
- `--trace`：追溯模式，不输出变更数组，改为输出
  `{"min_initial":…, "must_same":…}`（见下文「追溯模式」）。

退出码：`0` 成功；`1` 输入非法（整次拒绝）；`2` 用法或 IO 错误。

失败时 stderr 报告出错事件的**零基字节起点**（及零基事件序号），例如：

```
error: invalid event stream: event #1 (byte offset 41): event checksum mismatch
```

## 输入格式

每个事件 = 19 字节公共头 + 事件体 + 4 字节尾部 CRC32。

### 公共头（19 字节）

| 偏移 | 字段 |
|---|---|
| 0 | timestamp（4，忽略） |
| 4 | 事件类型（1） |
| 5 | server_id（4，忽略） |
| 9 | 事件总长度（4，小端，含头与 CRC） |
| 13 | log_pos（4，忽略） |
| 17 | flags（2，忽略） |

头部只用**类型**与**长度**两个字段，标志一律忽略。逐事件校验尾部
CRC32（zlib CRC32，对校验和前全部字节计算）。

### TABLE_MAP_EVENT（类型 19）

事件体：`table_id`(6) + flags(2，忽略) + 库名(1 字节长度 + 字节 + `00`)
+ 表名(同构) + 列数(lenenc，**必须为正**) + 列类型(每列 1 字节)
+ 元数据(lenenc 长度 + 块) + 可空位图(`(列数+7)/8` 字节)。

- 仅接受列类型 `LONGLONG`(8，有符号) 与 `JSON`(245)，其余拒绝。
- 元数据按列消费：LONGLONG 0 字节、**JSON 固定 4 字节**（内容忽略），
  总长度不符即拒绝。
- 可空位图之后**拒绝可选元数据**（事件体必须恰好耗尽）。
- 映射按 `table_id` 登记；同 id 的新映射**替换**旧映射。

### 行事件 V2（类型 30/31/32）

事件体：`table_id`(6) + flags(2，忽略) + `extra_data_len`(2，**固定为 2**，
其余拒绝) + 列数(lenenc，**须与映射一致**) + 出现列位图 1
+ （仅 UPDATE）出现列位图 2 + 行数据。

- `table_id` 必须引用已知映射。
- 每个出现列位图**至少须有一位置位**（尾位忽略后判定）。
- 行数据连续排列直至事件体耗尽：每行（UPDATE 为前行/后行成对）=
  NULL 位图（**按出现列压紧**，`(出现数+7)/8` 字节，尾位忽略）
  + 各出现非空列的值（按列号顺序）。缺列省略。
- **SQL NULL 须对应可空列且无载荷**，否则拒绝。
- 值：LONGLONG = 8 字节小端有符号；JSON = 4 字节小端长度 + json_binary 文档。

### json_binary 子集

4 字节小端长度之后：1 字节类型码 + 值。支持小/大容器、字面量、
整数（int16/uint16/int32/uint32/int64/uint64）与 UTF-8 字符串；
**拒绝 double(0x0b) 与 opaque(0x0f)**。

- 容器头：小容器 = 计数(2)+尺寸(2)，大容器 = 计数(4)+尺寸(4)；
  尺寸从本容器计数字段起算，不得越出所在区域。
- 对象键条目 = 偏移(2/4) + 键长(2)；值条目 = 类型(1) + 内联值或偏移(2/4)。
- **偏移均从本容器计数字段起算**；**内联与否按容器大小裁决**
  （小容器内联 ≤2 字节：literal/int16/uint16；大容器 ≤4 字节：另含
  int32/uint32）。
- 字符串 = lenenc 长度 + UTF-8 字节。
- 拒绝：越界、非法 UTF-8、对象重键、文档尾随字节；
  **不检查**键排序与内联填充字节。

## 输出格式

JSON 数组，按事件、行原序排列，每行一项：

```
[event, db, table, op, old, new]
```

- `event`：事件的零基序号（TABLE_MAP 也计入编号）。
- `op`：`"I"` / `"U"` / `"D"`。
- `old` / `new`：行镜像；插入时 `old` 为 `null`，删除时 `new` 为 `null`，
  更新时两者皆为镜像。
- 镜像：对象，键为**零基列号字符串**，值为标签数组：
  - `["sql"]` — SQL NULL；
  - `["int", n]` — 有符号 LONGLONG；
  - `["json", v]` — JSON 文档（`v` 为解析后的 JSON 值）。

示例：JSON 载荷 `04 00`（字面量 null）得 `["json", null]`；SQL 空值得
`["sql"]`；空输入文件得 `[]`。

## 追溯模式

```
python3 sparse_rows.py --trace INPUT [OUTPUT]
```

读取同一事件字节流（沿用全部原校验），按 **(库名, 表名)** 分组解释行
变更历史，输出 JSON 对象：

```
{"min_initial": k, "must_same": [[bool, ...], ...]}
```

- `min_initial`：解释全历史所需的**最少初始行数**（各组求和，非负整数）。
- `must_same`：按行变更原序、零基索引的布尔方阵，**仅当全部最优解释
  中两项属于同一身份**才为 `true`（对角线恒为 `true`，跨组恒为
  `false`）。

解释模型（按原序逐条解释）：

- 初始行各列为符合映射的**独立未知值**；
- 插入按新镜像建立新身份，缺列未知；
- 更新/删除选择一条存活行：旧镜像出现列须相等，未知列据此绑定；
- 更新只覆盖新镜像出现列；删除的身份不可复用；
- 未知值跨步骤保持；同值行仍为不同身份。

值比较：**标签参与比较**（`["sql"]` / `["int",n]` / `["json",v]` 两两
不同）；JSON 递归比较，对象忽略键序，布尔不同于整数。

限制：同组各映射的列类型与可空性须一致；每组最多 **12** 条行变更。
超限或映射不一致即**整次拒绝**，报告相关事件的零基字节起点；失败保留
旧输出文件，成功原子替换。

示例：单列依次更新 1 为 2、删除 2，得 `{"min_initial": 1,
"must_same": [[true, true], [true, true]]}`；空流得
`{"min_initial": 0, "must_same": []}`。

## 错误处理

截断、未知事件/列/JSON 类型、校验和不符或任何非法结构都导致**整次
拒绝**：不产生任何输出，以退出码 1 报错（含出错事件的零基字节起点）。
空文件是合法输入，输出 `[]`。

## 验收测试

```
python3 test_sparse_rows.py     # 或 python3 -m unittest -v
```

测试不引用被测模块的任何常量或构造器，全部事件字节（含 CRC32）由测试
文件按格式独立拼装，覆盖：规格示例（`04 00`、`["sql"]`、空文件）、
稀疏缺列、位图尾位、三类行事件、映射替换、事件编号、json_binary
大小容器/嵌套/Unicode/各整数类型，以及全部拒绝路径（截断、未知类型、
非法结构、double/opaque、重键、越界、尾随字节等）与 CLI 行为
（成功才替换输出、失败报告零基起点）。

追溯模式另有独立小例枚举核对：规格示例、后续观测排除早期匹配、重复行、
SQL 空值、标签参与比较、JSON 键序与布尔/整数、缺列绑定、部分覆盖更新、
删除身份不可复用、分组求和、映射不一致与 12 条上限的拒绝（含零基起点），
并与测试内独立重写的暴力枚举（链划分与过程语义两种）在穷举/随机小例上
逐项核对。
